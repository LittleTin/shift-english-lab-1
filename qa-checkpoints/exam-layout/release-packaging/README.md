# Local-only SHIFT release packaging proof

Do not checkpoint or publish the generated trees. Version `9.9.1` in the
example is just a local label, not a proposed release. This tooling never
pushes, publishes, changes the source tree, talks to production, or declares
the draft release-ready. Version selection, evidence completeness,
compatibility behavior in a real browser/phone, and hosting limits remain
separate gates.

## Input and output boundary

- Only edit split questions/groups/media in the canonical source. Manifest
  bindings check every required input's source path, size, and SHA-256. The
  current packs are generated by the existing layout compiler, not copied
  from a legacy checkout or editable duplicate. Release packaging does not
  replace evidence reconciliation; the sample remains an **unverified draft**.
- The code comes from a small explicitly listed shell dependency set, plus
  an intentionally supplied compatibility-patched app. The published
  root would contain the runtime shell, generated JSON/JS and reachable
  binary media only; there is no recursive copy of authoring/source,
  checkpoints, archives, browser fixture, tools, or release receipts.
- The stable-URL projection lays out ordinary text under `runtime/` and
  one physical object per distinct SHA-256 under `objects/`. The build
  receipt maps unchanged relative URL to object, extension, and consuming
  role. A same-origin server/host adapter must resolve that map, preserving
  content type, caching and Range/206 behavior. Do not upload this object
  directory directly to a generic static file host. Treat host adapters as
  unavailable until empirically verified. All pack URLs in this projection
  are literal originals and the compiled JSON/JS stays byte-identical.
- A separate local **static** projection can emit each exact binary once
  without special host support only if current aliases losing their old
  path have been explicitly proven never to have been published. It rewrites
  those references in generated current JSON/JS only, prefers a protected
  URL as target, rejects cross-extension sharing, and refuses if a retired,
  shell, published, or otherwise protected alias would disappear. Any exact
  unmodeled ancillary reference to a removed URL also blocks. Rewriting
  is scoped to candidate-only current generated paths, never canonical
  authoring paths; do not reuse the proof allowlist for release. Protect
  the winning URLs in subsequent releases. If no aliases can be remapped
  on a static host, stable old paths and one byte copy per SHA are mutually
  incompatible; fail rather than quietly break cached links or silently
  double-pack. Git blob dedup does not measure hosted bytes.
- Current plans and their explicitly declared fallback audio stay as-is:
  existing app can select those fallbacks. It does not include speculative
  unreferenced archive bytes. Remove historical plan refs, if eventually
  appropriate, only after a reviewed compatibility policy and browser tests.

## Unknown older sessions are not inferred

By default the compatible app ships with an empty resume catalog; an unknown
old version goes to the existing fail-closed path, not an active-pack regrade.
That protects answers but is **not** a substitute for testing supported old
continuation paths. Preserve prior content separately until this gate clears.

To exercise a genuinely supported prior snapshot, generate it with
`resume-compat/write_snapshot.py` using the immutable deployed commit and
independently verified actual interval, not a local date or Git commit date.
Add `scriptSha256` to each manifest `catalogEntries` record by hashing its exact
snapshot script; keep the prior manifest and verification record offline. Pass
`--old-overlay` plus `--old-policy` with keys `commit`, `version`, `from`,
`until` (epoch milliseconds), `manifestSha256` (including script hashes) and
a nonempty `deploymentEvidence` reference for an independent reviewer. The
packager verifies these bytes, scopes, compatibility manifest, and exact union
of referenced media; it cannot certify evidence provenance itself. Merely
matching the schema or calling a run approved is not proof. The known synthetic
fixture interval is explicitly rejected. No verified old deployment interval
was supplied for this proof, so positive production continuation is untested.
Exact prior bytes, if approved, are merged into the same content-addressed store;
a same-URL differing digest will block pending an explicit compatibility plan.

## Reproduce locally

```sh
D=shift-release-overlay
A=shift-media-migration/acceptance
for x in a b; do
  python3 "$D/package.py" --source "$A/source" --shell "$A/staged" \
    --authoring shift-qa/AUTHORING.md \
    --app shift-browser-preflight/fixture-with-filter/site/assets/app.js \
    --version 9.9.1 --output "$D/run-$x"
done
cmp "$D/run-a/receipt.json" "$D/run-b/receipt.json"
python3 "$D/make_fixture_allowlist.py" "$D/run-a" > "$D/unpublished-test.json"
python3 "$D/static_export.py" "$D/run-a" "$D/static-a" --unpublished "$D/unpublished-test.json"
python3 "$D/test_overlay.py" "$D/run-a" "$D/run-b" "$D/static-a"
python3 shift-qa/tools/validate_exam.py --site "$D/static-a/site"
```

The local `make_fixture_allowlist.py` helper enumerates canonical migration
names in this synthetic branch for controlled tests. It does not prove actual
publication history. Do not run it against a release candidate and assume its
output is a valid allowlist.

- Two builds yield exactly the same receipt SHA-256
  `f3d5fe4c631c35e1ed8477ee44957bf1680d021f4e108767d40579e59c8c6bc0`.
- 1,004 logical media routes, 846 unique binaries, 393,163,325 actual media
  bytes instead of 542,053,006, avoiding 148,889,681 bytes. Compiled JSON/JS
  and routing SHA verified against the exact migration draft.
- Static projection retains the current empty `.nojekyll` marker (GitHub Pages static mode), measures about 397 MB on this local candidate, and rewrote 158 aliases solely within the scoped unpublished
  active namespace; article/audio contents, URL-path-to-media hashes, keys
  and timing remained equivalent. Structural validator passed all three
  exams (200 active questions, 54 listening groups and 284 frames, 2700 s
  per exam, no archived IDs; 561 unique ranged audio media after dedupe).
- The actual browser smoke was not executed for this packaging task. Prior
  synthetic browser fixture HTTP proofs cover range mechanics, not a real
  host adapter for this new object projection. Run browser and HTTP
  acceptance against the exact selected packaging mode before release.

Eligible files to checkpoint: this README plus Python source only. Do not
include `run-*/`, `static-*/`, `unpublished-test.json`, caches, browser fixture,
authoring copy, CLI output, or any generated media.

### Candidate reserve exclusion

A complete replacement can live under `question-reserve/` in the work branch,
never in the website or its route/receipt. Packaging builds only the explicit
runtime allowlist and rejects reserve components in media paths, overlay
receipts, and generated trees. The negative test supplies a matching binary
hash under a reserve path and rejects it, then proves the same binary can be
accepted under a normal path. It also rejects a stray unmanifested reserve
directory. Never publish the source checkout; these file checks do not
replace verifying that each replacement is active in the final runtime pack.
