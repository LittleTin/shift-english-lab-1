# SHIFT account sync

SHIFT remains a static GitHub Pages site. Keep the existing test catalog, quiz/answer formats and Opus media. The optional Account & Sync section is hidden until a public project URL and browser publishable key are configured.

## User behavior

- Guest practice, unfinished sessions, backups, and existing local data work without an account. Signing in opens the account's separate workspace and does not upload or replace a guest session. Sign out and open Practice Home to continue a guest session.
- Sign-in uses email and password provisioned by the administrator. There is no public registration, sign-in email, or self-service reset. The right-hand header shows the actual tab's sign-in state. Refreshing the same tab reverifies the account using a rotating refresh handle stored only in its session storage; neither a password nor the bearer access token is saved there. Closing a tab or opening a separate browser can require sign-in. Until reverified after an offline refresh, the tab does not expose the cached account workspace. Reconnect never switches an open guest quiz or overwrites inputs the user is editing.
- A newly opened practice or timed test, even with zero answers, gets an owner-only checkpoint. Answers, group/question position, eligible practice-audio offset/speed/pause, formal timer and approved audio-resume cursor are saved first on the device, then queued for background sync. Cloud progress never pauses playback, replaces an open attempt automatically, or restarts the Reading time allowance. Audio always resumes only on a user tap. No network means no server receipt: the app says local/offline and retries when available. A very recent change must reach the cloud before another device can see it.
- Sign in with the same account on the second device and click the prominent Resume Practice or Resume Formal Test card. If both devices changed it, both versions are kept and the user selects one; choosing local does not silently overwrite newer remote progress. A choice saves the unselected snapshot on this device, accessible from Practice recovery. Stale devices cannot revive a completed session: the cloud tombstone is revisioned and a completed ID cannot reappear.
- Completed answers and derived mistakes still synchronize as immutable history. Notes, starred questions, attachments, custom pack files and preferences remain local; if a resumed session references a custom pack, install the same pack on the destination device first. No personal learner data is used in testing.
- `Data & Settings → Copy Guest History` gives a separate confirmation before uploading eligible previous sessions. This copies, not moves. Incomplete or oversized records remain local; they aren't silently discarded. Account “Export Backup” remains available; replacing/deleting synced history is intentionally not offered in v1. Guest backup import remains available.
- Browser resends use the same stable key. A conflicting snapshot is not overwritten. Automatic retries after reconnect do not mean that a failed/delayed write succeeded.
- Browser storage is isolated by **origin**, not URL path. The public launch origin must not serve unrelated or untrusted scripts, including another GitHub Pages project on the same account host. Prefer a dedicated HTTPS origin controlled by the owner for public sign-in. Do not migrate the guest cache to a new origin silently; users can export in the original site and import as guests at the new origin if needed.

## Provision the Free pilot

1. In the owner's verified Supabase account, create a clearly named, dedicated **Free** project in Tokyo if available (Singapore if needed and approved). Confirm Free status; do not add a paid plan, payment method, or optional paid service. Keep database credentials in Supabase/operator storage, never in Git, URLs, browser config, or chat.
2. Apply the files under `supabase/migrations/` in order to a fresh project. On an existing project apply only pending migrations. Keep the `shift_private` schema outside the PostgREST exposed schema list. Do not apply the synthetic test stubs. Verify anonymous requests are rejected and authenticated accounts can access only their rows. The browser key cannot bypass data policies. No admin, secret, or service-role key belongs in the frontend.
3. For the closed group, keep public signup and anonymous sign-in off. Leave Email enabled, disable magic links and email OTP, require the current password for password changes, and configure a minimum of 12 characters. Hidden or disabled settings cannot be replaced by browser validation. Keep email confirmation enabled. Provision only authorized learning identities through the project's Authentication → Users admin interface as confirmed accounts, not as Supabase organization members and not through public signup. Use unique temporary passwords supplied privately by the account administrator, never via a shared channel or this repository. Password changes run in the signed-in account; without a mail service, forgotten passwords are reset manually by the administrator after verifying identity. Reset the original identity in place, without deleting or recreating it: cloud history and on-device workspaces use the original Auth UUID. Check any optional Password Changed notification separately if enabling notices; do not use team membership as an email workaround.
4. Set `assets/shift-sync-config.js` to the verified project HTTPS origin and **publishable** key. Leave it blank on every other deployment. No changes to testing data, media, or website hosting. The dormant configuration is the rollback switch: disabling it stops new cloud traffic without altering existing data.
5. Before pointing regular visitors at the login, use isolated approved test identities to verify real password sign-in, password changes, and two-user isolation in the actual project, desktop and phone-width UI, two separate browser contexts, reconnect, refreshing/sign-out/account switching, expired token, zero-answer resume, a slow request during answering and playback, conflicting offline edits submitted from a newer device, formal timing handoff, explicit guest-history transfer and no transfer before consent. Use synthetic exercise records, not existing user history. Check that the unchanged guest app and site still work. Validate the correct deployment and a usable opt-out. Do not treat local HTTP or SQL tests as proof that live Auth and CORS work.

## Native QA in the assistant's cloud VM

Use a private managed preview of a local candidate copy with `sites-preview start <absolute checkout>`. Use only the printed loopback URL in the VM's managed Chromium. If the fixture runs through a development script, explicitly accept the daemon's `--host 127.0.0.1 --port <assigned port> --strictPort` and bind only loopback. Never register, upload, or publish an internal test as a replacement for this check.

Start with separate empty browser profiles when available. If the managed browser reuses a test origin, isolate fixture IndexedDB and local/session storage with distinct temporary key suffixes on the browser-only copy. Record the suffix-only difference; never clear existing data or publish test-only storage names. Use synthetic identities and practice results, note fixture vs. hosted results separately, and stop with `sites-preview stop` when done. Native Chromium testing does not certify real iPhone behavior.

## Data path and validation

An owner-only view plus a compare-and-swap write RPC expose one revisioned active checkpoint per account and preserve terminal submission even if an older app writes completed history. One immutable account-owned row per submitted session includes the full result and per-question attempt snapshots. Supabase RLS authorizes SELECT/INSERT only for the JWT owner, and the security-invoker RPC distinguishes inserted, already_exists, and conflict. Direct admin access is not used by the website. App-side IndexedDB protects account queues locally, avoids losing completed records in normal cross-tab writes, and holds corrupt/oversized snapshots out of sync rather than discarding them. The cloud can hold the owner's asserted practice data, not verified grading evidence.
