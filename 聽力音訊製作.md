# SHIFT Listening Audio Production

Students play pre-generated audio in the browser. No speech engine, API key, or synthesis service is needed at playback. The audio is original neural speech, not a recording by ETS or an official exam timetable.

## Sources and local build

- US and UK speakers use [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M) via [kokoro-onnx v1.0 release assets](https://github.com/thewh1teagle/kokoro-onnx/releases/tag/model-files-v1.0).
- Indian and Australian English use [MeloTTS-English](https://huggingface.co/myshell-ai/MeloTTS-English) with the supplier's `EN_INDIA` and `EN-AU` voice IDs. These are not gender variants of a single voice. Keep question dialogue roles stable.
- `tools/render_listening.py` reproduces the 1.1 passage audio; `tools/formal_audio.py` renders original directions, question cues, and bounded banks. Use separate authoring environments as needed, with model weights and caches outside the site. See `tools/melo-environment.lock.txt` for the pinned Melo environment.

## Formal exam and practice media

`listeningPlan.frames` combines passages, original directions, question numbers, spoken Parts 3–4 question stems, and silent answer windows. It targets 2,700 seconds per exam. Each frame has `groupId`, `kind`, `duration`, and scheduled time `at`; audio frames also carry `src`, `start`, and `end`. The browser times silence; it is not stored as a lengthy silent MP3.

When an audio bank contains more than one practice group, use `audioStart` and `audioEnd` to preserve group boundaries. Maintain the same question IDs when regenerating audio for unchanged text. Run `python tools/validate_exam.py` before publishing and smoke-test actual playback, including range requests in the hosted path. Structural and codec checks do not replace listening checks for pronunciation.
